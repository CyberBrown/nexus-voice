## Architectural Insight

The Qwen3-TTS architecture has a fundamental trade-off:
- **Base model** → Supports zero-shot voice cloning → Can use reference audio anchors
- **Fine-tuned (custom_voice)** → Specialized for one voice → No voice cloning support

**You cannot have both** - this is by design. The fine-tuning process specializes the model 
for a single voice identity, removing the generalization needed for voice cloning.

## Alternative Approaches

### 1. Instruction-Based Consistency (Tested - Works)
Use detailed instructions for emotional/prosodic control:
- "Calm, even pace, professional neutrality" ✓
- More specific: "Speak at 140 words per minute, flat intonation, medium-low pitch"

### 2. Multi-Anchor Pre-generation (Untested)
Pre-generate anchor clips for each emotion, then use them as examples in training:
- Generate "neutral", "warm", "emphatic" samples
- Include these in fine-tuning data with explicit emotion labels
- At inference, use emotion labels in instructions

### 3. Hybrid Architecture (Requires Different TTS)
Use a TTS that supports both:
- **XTTS v2** - Fine-tuning + speaker conditioning
- **Tortoise TTS** - CVVP conditioning with fine-tuned voice
- **Bark** - Semantic tokens + custom speaker embeddings

### 4. Two-Model Pipeline (Complex)
- Model 1: Fine-tuned Qwen3 for voice identity
- Model 2: Voice conversion model for prosodic transfer
- Combine outputs for consistent voice + dynamic prosody

## Recommendations

1. **Short term:** Rely on instruction-based control for the fine-tuned model.
   Use concrete, measurable instructions (pace, pitch range, energy level).

2. **Medium term:** Investigate XTTS v2 which supports both voice cloning AND 
   speaker fine-tuning simultaneously.

3. **Long term:** Consider a two-stage approach - generate with Qwen3-TTS, 
   then apply prosodic transfer with a dedicated model.

Direct, specific instructions outperform vague reference-based instructions.
